# Menu item AR recovery

The migration adds three service-role-only tables (`restaurant_ar_access`, `menu_item_ar_versions`, `menu_item_ar`), read/write RPCs, menu invalidation triggers on the two pointer tables, and lets the media pipeline accept GLB/USDZ up to 10 MB (bucket limits plus a shape-checked patch of `media_command_core`).

Fastest safe stop: turn AR off per restaurant (`update restaurant_ar_access set enabled = false`) or for everyone (`update restaurant_ar_access set enabled = false where enabled`). `read_published_menu_ar` then returns nothing and the public menu falls back to photos; the trigger bumps the menu revision so caches follow.

Full removal, if ever needed: drop the RPCs, then `menu_item_ar`, `menu_item_ar_versions`, `restaurant_ar_access`; delete `media_asset_references` rows with `target_table = 'menu_item_ar_versions'` so the model assets become deletable from Dosyalar; restore the 8 MB limit and image/video MIME list on `restaurant-media-staging` and `restaurant-media-sources`, and re-apply the original upload check/reservation lines in `media_command_core` (text in `20260921120000_media_library.sql`). Uploaded model assets are ordinary media assets and are cleaned up through the existing Dosyalar delete flow. Production requires the existing target-specific backup/release process.
